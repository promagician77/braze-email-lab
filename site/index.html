      How I'd approach your refresh

      Your data stays exactly where it is. The template is split in two: the data layer at the top (event properties, the Catalog lookup, the Selection) is copied as is, and only the presentation below it changes. One of the tests compares that data layer byte for byte against the original, so "logic unchanged" is checked, not promised.

      Dark mode is three different problems. Apple Mail and iOS follow prefers-color-scheme. Outlook.com and the Outlook apps partly invert colors, and respond to [data-ogsc] rules. The Gmail apps ignore both and force their own inversion. So each block gets explicit dark styles, the logo ships as two files, and bottle photos sit on a fixed light tile, since transparent bottles vanish on dark backgrounds.

      Outlook desktop renders with Word. Layout is tables only, widths are set in attributes, and the button has a VML version so it keeps its shape and color there.

      Gmail clips emails over about 102 KB. Content Blocks inside Catalog loops add up quickly, so the build measures every template. This one is well under.

      The previews here are approximations. For the real work I'd test every block in Litmus or Email on Acid across Outlook desktop, Outlook.com, Gmail, Apple Mail, and iOS, and include the screenshots in the handoff.
